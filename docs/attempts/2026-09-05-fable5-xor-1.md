## The closure theorem: ROT on an input-derived value is *necessary*

`reach.c` runs the BFS every xor record has asked for, per input, over the
full 10-trit accumulator space (59049 states):

| walk op set (upper envelope, layout ignored) | reachable | worst min-depth |
|---|---|---|
| `crazy(acc, v)`, v any byte 33..126 | **193/256** | 3 |
| + `rotr(acc)` | **256/256** | 5 |
| + `crazy(v, acc)` (roles swapped) | 256/256 | 4 |

The 63 unreachable inputs under pure CRZ are structural (they include the
whole band 96..159 and 243..255). This is an upper envelope over **every**
architecture that carries per-input information only through A against
byte-valued operands — table walks at any stride, any K0, any depth, any
program length. Consequences:

- The 68/256 and 77/256 ceilings of the classic family were never going to
  reach 256; no pure-CRZ family can pass 193, and sharing eats it to ~70.
- One `rotr` acting on an input-derived value, placed *per input*, closes the
  gap to 256/256 at depth ≤ 5. The whole rung is the mechanics of buying that
  per-input ROT timing inside 256 bytes.

## Four mechanized attempts to buy it, all measured exactly

**1. Premix (`rotr^j(b)` seed, shared j).** New fully loader-legal layout:
park b at (71,72), copy-park at (106,107) — both 121-pairs exist and both are
MOVD-addressable — rotate the copy with a 3-instruction cycle through pinned
pointers {74:101, 85:71, 86:106, 108:85, 109:84}, then re-dispatch D = b+1 off
the untouched m[72]. Exact DP (`dpk2.c`), sweep j=1..7 × k ∈ {3,5} × K0 ≤ 16:
**best 54/256** (j=7, k=5). A shared rotation adds no per-input freedom; it
only re-poses the same sharing problem against worse targets.

**2. Shorter programs (the record's unturned stone).** `dpk` with L swept:
L=180 → 46, 200 → 53, 232 → 63, 248 → 68, 256 → 68 (k=5 optima, exact).
Monotone: crazy-fill operands break the trit-magnitude barrier but carry zero
design freedom, and freedom is what is scarce. **The L-sweep is closed: length
below 256 strictly loses.**

**3. JMP code dispatch without D-repointing.** `jdp.c` bounds the family the
push record measured at 48–53: entry C = b+1, shared operand stream from
D = 73, private per-cell ops in {NOP, CRZ, ROT, OUT, HALT}. The independent
(free-code) bound over **all 8^5 operand streams**: **max 36/256**. So private
code with a shared operand stream is worth no more than the straight-line
family (34), and the 48–53 previously searched came entirely from D-repointing
ops, i.e. from private *data*. Code privacy is not the resource; data privacy
is.

**4. Post-fold through a funnel (new architecture).** After the walk, 7 MOVDs
collapse the polluted D onto a funnel re-derived to live above the code zone
(26 pins, root 114, exit pin 121:71 landing D = 72), where m[72] = b lets the
program fold the walk value against the input itself — `crazy(w(b), b)` — then
apply shared S/R ops at cell 72. Exact DP (`dpk3.c`) over patterns to depth 3:
**best 4/256.** The funnel forces every walk-end cell in [K0+k, 255+K0+k] down
from 8 legal bytes to the ~2.4 whose value+1 lands in the tree, and that
alphabet restriction destroys more window freedom than the per-input operand
gains. **This transfers: any funnel-based second dispatch pays this alphabet
tax on the whole table. The xor-2-multicase plan of "build the funnel, rerun
the DP with 28 pins" underprices the funnel by an order of magnitude — the
cost is not the pins, it is the source-range alphabet.**

## Where this leaves the rung

Every mechanically realizable family measured to date, at this cap:

| family | exact ceiling | measured by |
|---|---|---|
| straight-line CRAZY/ROT | 34 | len4096 corpus (exhaustive) |
| JMP code dispatch, D-invariant | ≤ 36 | jdp.c, all streams |
| premix rotr^j + walk | 54 | dpk2.c |
| classic walk, L < 256 | ≤ 68 (mono. in L) | dpk L-sweep |
| classic walk, L = 256 | **68** | dpk (record), reproduced |
| classic free-layout bound | 77 | dpxor.c (record) |
| post-fold via funnel | 4 | dpk3.c |
| any pure-CRZ architecture | ≤ 193 | reach.c closure |
| CRZ + per-input ROT timing | 256 possible | reach.c closure |

The 68 program is at the exact optimum of the only family that survives, and
the closure says no refinement of that family passes 193. What no record has
priced is **data-dependent control flow**: a self-modifying JMP loop whose
trip count varies with the input would deliver per-input ROT counts through
shared code — the one resource the closure says suffices — at a byte cost no
DP here has modelled. That is the single door left open, and it is where the
next serious attempt should spend its entire budget.

## Budget

Roughly 145k tokens of a 600k cap, ~55 minutes wall. With more budget: model
the self-modifying-loop family (JMP whose pointer cell is CRZ-written in the
loop body; state = (A, pointer cell, C-phase); the question is whether any
loop gadget yields per-input effective ROT counts with an in-loop byte cost
under ~40 cells), and only then re-approach the multicase rungs, which
inherit everything here plus the funnel alphabet tax.
