## Construction

The prefix uses the corpus's two-CRAZY, 121/121 input-copy construction, then nine ternary rotations to store `3*b` in cell 107. A short bootstrap places execution above the data table. The shared arithmetic routine begins at code address 937.

For input `b`, seven source cells begin at `124 + 3*b`. Five are mutable arithmetic operands, the sixth is initially a return pointer, and the seventh supplies a final arithmetic operand. All source bytes obey the classic loader's eight-opcode alphabet. Neighboring inputs share four of their seven initial source cells; their executions still start from separate fresh VM states.

The five-cell arithmetic window is visited eight times. The ROT masks are:

```
3, 20, 21, 18, 19, 24, 16, 7
```

Bit `j` selects ROT at cell `j`; otherwise the operation is CRAZY. After the first seven passes, MOVD reads the sixth cell, four more MOVDs converge to a fixed absorbing pointer at address 88, and a short exit route reloads `3*b`. Then 123 NOPs return D to the start of the input's window. These routes preserve A.

After the eighth pass, the routine no longer needs its return pointer. It performs CRAZY on that sixth cell and then on the seventh cell, outputs A's low byte, and halts. The 772-byte overlapping table and the shared routine fit in 2,028 source bytes.

The table is synthesized jointly for all inputs by exact max-sum dynamic programming with 4,096 boundary states. The state retains the four source bytes shared by adjacent input windows. Return-pointer legality is enforced inside every transition, and the simulated arithmetic includes writes back to the mutable table cells. The native VM remains the authoritative verifier.

## Search and evidence

The campaign first adapted the published shifted dispatcher and verified 94/256 with a shared table, then 219/256 with repeated passes. A much shorter `3*b` prefix made room for eight passes. Exact shortest paths to an absorbing return pointer replaced heuristic pointer-tree optimization.

Arithmetic sweeps and evolutionary mutations produced native milestones of 235, 252, and 254 out of 256. Reusing the pointer as arithmetic data after the last return produced 253 and then 255. The last failure was input 157. Keeping the arithmetic sequence and moving the return root from 67 to 88 produced the complete solution. The winning router has 76 usable pointer values; the earlier router had 77. Their identities and interaction with the overlapping table mattered more than the count alone.
