## Why this rung, and why not a lane

The board's note recorded the best known coverage as 27/256, reached by an
identity-dispatch program with roughly 27 per-input lanes and a shared pointer
pool that "runs out near 30 lanes". Adding five more lanes to that architecture
is the map8/map12 problem again — and map12-hi has two recorded, convergent
negative results.

So this attempt asked a different question: forget lanes, how far does a single
**straight-line** data path get? A program with no branching computes one fixed
function of the input byte, and a fixed function can only be right on the inputs
where it happens to agree with `b XOR 0x51`. The question is how large that
agreement set can be — which turns out to be answerable exhaustively.

## The family, and its exact ceiling

After `IN`, the only things a straight-line classic-Malbolge program can do to
the accumulator are `CRAZY` against a memory word and `ROTATE`. Both act one
trit position at a time. `CRAZY` with a constant applies, at position `i`, the
unary trit map `m_{c_i}` drawn from

    m0 = (1,0,0)   m1 = (1,0,2)   m2 = (2,2,1)

and `ROTATE` cyclically permutes positions. Because the constant's trit at each
position is free, N CRAZY ops with R rotations realise exactly

    out = sum_i g_i( trit_{(i+R) mod 10}(b) ) * 3^i ,   output byte = out mod 256

with each `g_i` any length-N composition of `{m0,m1,m2}`, chosen independently
per position. Input trits 6..9 are always zero (a byte is < 3^6), so those four
positions contribute a constant `K`.

The ceiling script enumerates that family exhaustively — every N,
every shift R, every per-position map, every achievable K. `M_N` saturates at
twelve maps and alternates between two twelve-element sets from N = 4 on, so
N = 0..5 covers every N:

| N | best over all shifts | |
|---|---|---|
| 0 | 0 | |
| 1 | 10 | |
| 2 | **34** | at shift 0 |
| 3 | 16 | |
| 4 | **34** | at shift 0 |
| 5 | 16 | |

**34/256 is the exact ceiling of the entire straight-line family.** That clears
cov32's threshold of 32 and cannot reach cov36. It is a structural statement,
not a search budget: past 34, coverage requires input-dependent branching.

The optimum has a clean reading. At N = 2, shift 0, with `g_i` = identity for
i = 0..5, the program computes `out = b + K`; with `K = 81 = 0x51` that is
`b + 0x51`, which equals `b XOR 0x51` on exactly the 32 bytes with
`b AND 0x51 == 0`. The two extra hits at 34 come from one non-identity map at
trit position 4. This attempt ships the 32 point, which is what the rung asks
for and needs a strictly simpler operand pair.

## The obstruction: every natural operand has flat high trits

Identity at a position needs `m1` twice, so both CRAZY operands must carry trit
1 at positions 0..5; positions 6..9 must carry a pattern whose h-values sum to
K = 81. No operand available for free can do that:

- **Source bytes.** A byte is < 3^5, so its trits 5..9 are all zero. Every
  CRAZY against a byte applies `m0` at all five of those positions, which forces
  `K` to 0 (N even) or 232 (N odd). Never 81.
- **Crazy-fill cells.** Memory past the program is filled by
  `mem[i] = crazy(mem[i-1], mem[i-2])`, which is position-wise, and both seed
  cells are source bytes with zero trits at 5..9. Those five positions therefore
  evolve through *identical* state, so every fill word in the machine has flat
  trits 5..9. (They are also eventually periodic with period 2 or 3 per position,
  so the far fill region holds only six distinct words.)
- **Words manufactured by CRAZY.** `crazy(0, byte)` has trits 5..9 all 1;
  `crazy(59048, byte)` has them all 0. Position-wise ops preserve "positions
  5..9 all equal".

So flatness at trits 5..9 is an invariant of everything reachable without a
`ROTATE`, and `K` is confined to {0, 208, 232}. **A rotation is not an
optimisation here, it is a necessity** — the only operation in the instruction
set that can break the symmetry among high trit positions.

## Construction

The operands are manufactured at run time as

    c = rot^5( crazy(0, x) )

`crazy(0, x)` has trits in {1,2} with positions 5..9 pinned to 1; rotating five
places moves those five pinned 1s down to positions 0..5 (satisfying the
identity requirement, given `x`'s trit 0 is not 2) and lifts `x`'s trits 1..4
into positions 6..9, where they are free. Seeds 79 and 123 give the operand pair
`c1 = 39001` and `c2 = 30253`, whose high patterns (2,2,2,1) and (2,1,1,1) sum
to exactly K = 81.

Layout follows from one observation about the loader. If every prefix cell holds
the unique byte that decodes to NOP at its own address, then after C walks the
prefix, cell `a` holds `x(a) = encipher(nop_byte(a))` — and that single table
does double duty:

- `x(q)` is the seed byte that manufacturing cell `q` offers;
- a cell with `x(a) = q-1` is a ready-made "MOVD to q" pointer, since MOVD sets
  `D = mem[D]` and the post-instruction increment supplies the +1.

Data cells therefore live at addresses 34..127 (a pointer value must itself be a
printable byte), and the builder just walks D forward, emitting NOPs, until it
lands on a cell whose value is the pointer it wants. No search, no backtracking:
33 non-NOP instructions inside 596 bytes.

    MOVD 114, CRAZY            mem[114] = crazy(0, x(114)=123)
    (MOVD 114, ROT) x 5        mem[114] = rot^5(...) = 30253,  A = 30253
    MOVD 79, CRAZY             A = crazy(30253, x(79)=94) = 0        <- zero A again
    MOVD 86, CRAZY             mem[86]  = crazy(0, x(86)=79)
    (MOVD 86, ROT) x 5         mem[86]  = rot^5(...) = 39001
    IN                         A = b
    MOVD 86,  CRAZY            A = crazy(b, 39001)
    MOVD 114, CRAZY            A = crazy(A, 30253)
    OUT, HALT                  emits A mod 256 = b + 0x51

The scratch step at cell 79 matters: the first manufacture needs `A = 0`, and
after five rotations `A` holds the finished operand. `crazy(A, x)` returns 0 when
every trit of `x` is 0 where `A`'s trit is 2 and in {0,1} where it is 1 — which a
plain byte satisfies for any `A` whose trits are all nonzero. One instruction
resets the accumulator so the second operand can also be built from zero.

## Verification

```sh
cargo run -p harness -- verify --rung L2.C0.xor51-cov32 \
    --program solutions/cov32/cov32-two-crazy.mal --verbose
# RESULT: PASS (native evaluator)   32/256 correct (>= 32 required)
```

Coverage rungs are seed-independent (all 256 inputs are enumerated), so one
epoch is definitive. The program halts on all 256 inputs; the longest run is 595
steps against a 2048 limit, and it is 596 bytes against a 4096 limit. Against
`L2.C0b.xor51-cov36` the same program scores 32/256 and correctly FAILs.

## What this leaves for the next attempt

- cov36 and up are **not** reachable by lengthening this program. The
  straight-line ceiling of 34 is exhaustive over the family, and the two hits
  past 32 sit on one trit position, not on a new mechanism.
- The honest next step for cov36 is hybrid: this 32-hit backbone plus four
  input-dependent lanes, or the old 27-lane dispatch pushed past its pointer-pool
  wall. Both are the finite-map problem again.
- The reusable pieces here are the operand invariant (flat high trits without a
  ROTATE, so any construction needing a specific `K` must rotate) and the pointer
  table `x(a)`, which turns "MOVD to an arbitrary data cell" into a lookup rather
  than a search. That table is not coverage-specific.
