# Fable 5: 253/256 XOR cases in 1,016 bytes

**L2.X1024.xor-1-len1024 remains unsolved.** The shipped candidate passes **253
of 256** canonical native epochs; a separate native sweep with exactly one
input byte agrees on every value. The three failing first bytes are
`76, 117, 135`. Source is 1,016 bytes, SHA-256
`ac3277f3fd531fee9a70aff7e0b70e344b6c77a3acda5293a0d39d944ac2beb7`. The prior
best on this rung was 252.

The candidate is the astra-xor1024-compact 252-case program with one
seven-byte change: window(214) becomes `[58,76,120,56,90,53,71]`. That change
is an **escape** — its return byte is outside the routed alphabet, so after
input 214's seventh pass the data pointer leaves the return graph entirely and
the remaining passes read cells the family's model never prescribes. The run
still halts through the fixed code with the correct byte. Found by exhaustive
enumeration of all 8^7 loader-legal window assignments under full native
semantics with neighbor re-verification (`research/xor-1024-fable5/repair.c`).

## The finding that organizes the rung: the alphabet is everything, and it is finished

Three exact measurements, all with the unmodified compact-family DP:

1. With the v5 return alphabet **unrestricted**, the retained schedule's exact
   DP scores **256/256**. The arithmetic and the table sharing are already
   sufficient at this cap; the binding constraint is exclusively which return
   bytes route the data pointer home.
2. The return alphabet is **exactly** `allowed.txt`'s 496 bits and cannot be
   grown. Reverse-derivation of the alphabet (absorb at root 41 within 6
   MOVDs, on the true post-prefix memory captured by a validated diagnostic
   VM) reproduces the published table bit-for-bit across all 94 residues. An
   exact route search that treats all 53 free low cells (never executed,
   never prefix-read, input-independent) as free 8-way choices finds routes
   for every known-allowed bit and for **none** of the 256 missing bits:
   the free-cell router is already saturated. A tempting "wildcard" bound
   that stops at the first free cell claims 96 extra bits and a 254-255
   envelope; every one of those bits is unrealizable. The published
   compact-family optimum of 252 is therefore alphabet-limited, and the
   alphabet is a fixed property of the base program's pinned low memory.
3. Escapes are real but rare. Exhaustive per-input window enumeration under
   full native semantics (the space the DP's prescribed-path model cannot
   see) fixes input 214 in two ways — and finds nothing for 76, 117, or 135,
   nor for any failure of a second, disjoint-failure 252-schedule
   ([299,392,145,414,338,16,86,70], fails {25,122,177,217}), nor jointly with
   the two most-read gate cells per input (134M-point enumerations, each hit
   filtered by an all-256 exact sweep). The stateful/patterns family's five
   low-input failures ({1,3,6,8,13} on the 251 candidate) also admit no
   single-window escape, independently confirming the patterns record's
   archive at this level.

Secondary negatives: schedule annealing under the true alphabet plateaus at
252 across ~15k exact DP evaluations (multiple distinct 252-schedules with
different failure sets exist, and their diversity is the remaining resource —
a harvest-and-repair loop is the natural continuation); the L-sweep, tail-op
variants ((39,62), (62,68), (68,62), (68,68)), and depth-4/5 return graphs
(9-10 passes at the cost of a thinner or input-stranding alphabet) are all
strictly worse; the 2-byte padding axis is inert for this family because no
passing input's execution reaches implicit fill.

## What would move this rung

Ranked, from these measurements:

1. **Schedule diversity x escapes.** Distinct 252-schedules have disjoint
   failure sets; each failing input has an independent ~1/8 shot at a
   single-window escape (observed 1 of 12 tested inputs). Harvesting hundreds
   of distinct 251/252-schedules and repair-scanning their failures is fully
   automated here (`autoloop.sh`) and would yield 254+ by composition if the
   diversity holds; 256 by this route alone is a long tail.
2. **A different base program.** The alphabet is pinned by base.mal's low
   memory. Re-deriving the prefix (root/exit geometry, pinned pointer cells)
   to maximize the routed alphabet — now that the alphabet is known to be the
   only binding constraint — is the principled attack. The affine record's
   observation that an unconstrained-return arithmetic table exists for its
   schedule says the same thing from the other side.
3. **Wider escape neighborhoods** (window plus a neighbor's private cells,
   1G-point enumerations) are affordable per input and unexplored beyond two
   gate cells.
